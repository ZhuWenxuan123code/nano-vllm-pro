### flash-attn 构建说明

`flash_attn_2_cuda.cpython-310-x86_64-linux-gnu.so` 为本地编译（非 PyPI 官方 wheel）：动态链接 `libcudart.so.13`，内嵌 cubin 目标架构仅有 `sm_80` / `sm_90` / `sm_100` / `sm_120`（外加 `compute_120`），不含 `sm_86`。3090 依 CUDA 次版本向前兼容规则落到 sm80 kernel 上，功能正常，但未使用 sm_86 专属调优。

该构建的 `flash_attn_varlen_func` 额外支持 `block_table` 参数（标准 FA2 的 varlen 无此参数），且其 C++ 层断言分页 KV 的 block size 必须为 256 的整数倍——与 `config.py` 中 `assert self.kvcache_block_size % 256 == 0` 成对，因此 `kvcache_block_size` 不可改为 256 的非整数倍。

### 测量注意事项

- **独占 GPU**：benchmark 默认使用 `cuda:0`，而 KV cache 容量按剩余显存推算（`model_runner.py` 的 `allocate_kv_cache`）。同卡若存在其他进程，`num_kvcache_blocks` 会被压缩并引发大量抢占，吞吐与 TTFT 均不可比。建议用 `CUDA_VISIBLE_DEVICES` 指定空闲卡后再测量。
- **CUDA Graph**：`enforce_eager=False` 时 decode 走 graph replay；PyTorch 的 arch list 含 `sm_86`，运行时无需 JIT。
- **TF32**：`torch.backends.cuda.matmul.allow_tf32 = False`（默认值），`cudnn.allow_tf32 = True`。bf16 推理不受影响。
- **tokenizer 不计入吞吐**：benchmark 传入的已是 token id，`add_request` 会跳过 `tokenizer.encode`。
