# nano-vLLM 推理算子融合与性能优化

技术栈：Python、PyTorch、Triton、CUDA Graph、Nsight Systems

- **算子融合（P2）：**实现 Decode Q/K RMSNorm、RoPE 与 Paged KV Cache 写入的 Triton 融合 kernel，支持 GQA、FP16/BF16 与 Graph padding；B=64、BF16 下单层链路由 5 个 kernel 减至 1 个，延迟下降 **73.5%**；相对现有 compiled 路径，Decode-heavy 端到端吞吐提升 **2.17%**，完整模型 Decode kernel 次数减少 **25.7%**。
- **输入缓冲复用（P3.1）：**复用 pinned CPU/GPU 缓冲，增量更新 block table，并让 CUDA Graph 直接引用持久化输入；稳定 B=64 Decode 每步输入 H2D 从 **6 次降至 2 次**、D2D 拷贝从 **5 次降至 1 次**，P2 关闭时 Decode-heavy 端到端吞吐提升 **1.55%**。
- **Paged Attention（P4.1）：**实现高精度 Triton Paged GQA Decode Attention，通过同组 Q heads 复用 K/V、在线 softmax、FP32 累加及 split-KV 归约优化计算；相对 FlashAttention BF16，Decode-heavy 端到端吞吐提升 **12.52%**，TPOT P50 从 **21.18 ms 降至 18.86 ms**。
- **KV Cache 量化（P4.2～P4.3）：**实现 K 每 32 维分组、V 每 token/head 的 INT8 缓存与 kernel 内反量化，兼容分块 Prefill、Prefix Cache 及 P2 融合写入；每 token KV 存储含 scale 减少 **46.09%**，同显存预算 token 槽位增加 **85.65%**。固定 WikiText-2 子集的 2K/8K 续写困惑度相对 BF16 增幅分别为 **0.324%/0.697%**。
- **正确性验证：**实现可切换的 Triton RMSNorm / Add-RMSNorm；累计 **67 项回归测试通过**，覆盖数值、分页缓存、teacher-forced logits、CUDA Graph 捕获/重放及 TP=2 冒烟；区分量化误差与 kernel 实现误差。
- **性能评测：**扩展 batch、序列长度、后端与 TP 配置，固定 seed 并完成代表性预热；结合 `torch.profiler`、Nsight Systems 分析 Prefill/Decode，自动生成吞吐、TTFT/TPOT 与多轮 A/B 报告，P4 完成 **95 次端到端对照**。

测量口径：RTX 3090、Qwen3-0.6B、单卡 CUDA Graph；端到端吞吐提升取各阶段独立 A/B 的五轮中位数，不累加为整体收益。P3.1 仅复用缓冲，未实现异步流水线；INT8 当前同负载吞吐回退，仅报告容量收益，不将 KV 存储减少写成总显存减少。
