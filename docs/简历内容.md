# nano-vLLM 推理算子融合与性能优化

技术栈：Python、PyTorch、Triton、CUDA Graph、Nsight Systems

- **算子融合（P2）：**实现 Decode Q/K RMSNorm、RoPE 与 Paged KV Cache 写入的 Triton 融合 kernel，支持 GQA、FP16/BF16 与 Graph padding；B=64、BF16 下单层链路由 5 个 kernel 减至 1 个，延迟下降 **73.5%**；相对现有 compiled 路径，Decode-heavy 端到端吞吐提升 **2.17%**，完整模型 Decode kernel 次数减少 **25.7%**。
- **输入缓冲复用（P3.1）：**复用 pinned CPU/GPU 缓冲，增量更新 block table，并让 CUDA Graph 直接引用持久化输入；稳定 B=64 Decode 每步输入 H2D 从 **6 次降至 2 次**、D2D 拷贝从 **5 次降至 1 次**，P2 关闭时 Decode-heavy 端到端吞吐提升 **1.55%**。
- **Paged Attention（P4.1）：**实现高精度 Triton Paged GQA Decode Attention，通过同组 Q heads 复用 K/V、在线 softmax、FP32 累加及 split-KV 归约优化计算；相对 FlashAttention BF16，Decode-heavy 端到端吞吐提升 **12.52%**，TPOT P50 从 **21.18 ms 降至 18.86 ms**。
- **KV Cache 量化（P4.2～P4.3）：**实现 K 每 32 维分组、V 每 token/head 的 INT8 缓存与 kernel 内反量化，兼容分块 Prefill、Prefix Cache 及 P2 融合写入；每 token KV 存储含 scale 减少 **46.09%**，同显存预算 token 槽位增加 **85.65%**。固定 WikiText-2 子集的 2K/8K 续写困惑度相对 BF16 增幅分别为 **0.324%/0.697%**。
- **在线混合调度（P5）：**实现 Decode 优先的 Prefill/Decode 混合前向，共享投影 GEMM，结合 KV 准入保护与等待保护；相对 legacy，稳定到达负载（27.52 req/s，即基准处理速率的 90%）端到端吞吐提升 **16.09%**；建立固定到达轨迹、逐 token ITL 与 SLO 有效吞吐评测，完成 **282 次实验及结果审计**。
- **正确性验证：**实现可切换的 Triton RMSNorm / Add-RMSNorm；累计 **87 项回归测试通过**，覆盖数值、分页缓存、teacher-forced logits、混合调度、CUDA Graph 捕获/重放及 TP=2 冒烟；区分量化误差与 kernel 实现误差。
- **性能评测：**扩展 batch、序列长度、后端与 TP 配置，固定 seed 并完成代表性预热；结合 `torch.profiler`、Nsight Systems 分析 Prefill/Decode，自动生成吞吐、TTFT/TPOT 与多轮 A/B 报告，P4 完成 **95 次端到端对照**。

测量口径：RTX 3090、Qwen3-0.6B、单卡；纯 Decode 使用 CUDA Graph，P5 混合批次使用 Eager。端到端吞吐提升取各阶段独立 A/B 的五轮中位数，不累加为整体收益。P3.1 仅复用缓冲，未实现异步流水线；INT8 当前同负载吞吐回退，仅报告容量收益，不将 KV 存储减少写成总显存减少。P5 的 16.09% 来自固定 mixed 策略及准入管理的整体对照，仅适用于所测稳定负载，不代表所有负载或 SLO 均改善；自适应策略未取得收益，默认仍为 legacy。详见 [P5 验收报告](优化/P5-混合调度与自适应预算.md)。


# nano-vLLM 推理算子融合与性能优化（简历优化版）

技术栈：Python、PyTorch、Triton、CUDA Graph、Nsight Systems

- **Paged Attention：**实现 Triton Paged GQA Decode Attention，结合 KV 复用、在线 softmax 与 split-KV 归约；在 RTX 3090、Qwen3-0.6B 的 Decode-heavy 负载下，相对 FlashAttention BF16，端到端吞吐五轮中位数提升 **12.52%**，TPOT P50 从 **21.18 ms 降至 18.86 ms**。
- or
- **Paged Attention 优化：**实现支持 GQA、在线 softmax 与 split-KV 的 Triton 分页 Decode Attention，针对 RTX 3090 优化计算分块与 KV 复用；在 Qwen3-0.6B Decode-heavy 基准中，相对项目原 FlashAttention BF16 路径，端到端吞吐提升 12.52%（五轮中位数），TPOT P50 从 21.18 ms 降至 18.86 ms。
- **Paged Attention 实现与调优：**使用 Triton 实现支持 GQA、在线 softmax 与 split-KV 的分页 Decode Attention；通过分块消融及 Nsight 资源分析，验证小分块在所测 Decode 形状下的优势；在 RTX 3090、Qwen3-0.6B Decode-heavy 基准中，相对项目原 FlashAttention BF16 路径，端到端吞吐提升约 12.5%（五轮中位数，独立复验一致）。
- **KV 缓存量化：**设计 K 每 32 维分组、V 每 token/head 的 INT8 缓存及融合反量化，兼容分块 Prefill 与 Prefix Cache；含 scale 的 KV 存储/token 减少 **46.09%**，同显存预算槽位增加 **85.65%**；固定 WikiText-2 子集 2K/8K 续写困惑度增幅均低于 **0.7%**。
- **Decode 链路融合：**实现 Q/K RMSNorm、RoPE 与分页 KV 写入的单 kernel 融合，支持 GQA、FP16/BF16 和 CUDA Graph；B=64、BF16 下单层链路由 **5 个 kernel 减至 1 个**，延迟下降 **73.5%**，完整模型所测 Decode kernel 数减少 **25.7%**。
- **工程验证：**建立可切换后端、固定种子及五轮 A/B 基准，使用 Nsight Systems 定位执行瓶颈；完成 **87 项回归测试**，覆盖数值、缓存生命周期、混合调度、CUDA Graph 与 TP=2 冒烟。

投递口径：以上为各阶段独立实验，不累加收益；INT8 仅报告存储与容量成果，当前同负载吞吐回退，不称为量化加速。详细结果见 [P2](优化/P2-Decode融合QK-RoPE-KV.md) 和 [P4](优化/P4-INT8-KV与PagedAttention.md)。

系统方向可选替换最后一条：**在线调度：**实现 Decode 优先的混合前向、KV 准入与等待保护，构建逐 token ITL/SLO 有效吞吐评测并完成 282 次实验审计；固定 mixed 策略在稳定到达 27.52 req/s 下，相对 legacy 总体吞吐提升 **16.09%**，但 TTFT P99 回退，收益不适用于所有负载，自适应策略未取得收益。

# 等待优化的内容

以下均为待办，不属于已完成成果；优先补强证据，再按算子或系统岗位选择一条深入，不预设收益百分比。

## 优先级 1：补强现有实验与收益归因

- **P2 交错复测：**现有原路径与融合路径分组先后运行，吞吐区间有重叠。固定 GPU、代码、预热及负载，每轮轮换后端顺序，至少五轮；保留每轮数据及波动，检验 2.17% 端到端收益是否可重复，必要时修订旧结论。
- **P5 准入消融：**在相同到达轨迹和缓存容量下，对比 legacy、仅准入保护、准入保护＋固定混合调度；明确驻留上限等差异，拆分减少抢占/重计算与混合前向的贡献。同步报告吞吐、TTFT、ITL、有效吞吐和 SLO miss，不只展示 16.09%。

## 优先级 2：INT8 Attention 执行效率（算子主线）

- **先定位：**对照高精度与 INT8 的相同形状，分析 scale 加载、转换/反量化、分页访存及归约成本；必要时采集 Nsight Compute 指标，区分测量证据与瓶颈假设。
- **再优化：**逐项评估 scale/数据加载布局、同组 Q heads 的 KV/scale 复用，以及 INT8 专用 tile、warps、split 规则；每次单项改动保留多形状数据，避免仅优化一个 batch。
- **验收：**覆盖短/长上下文和不同并发，比较单层延迟及同负载端到端表现；保持数值验证、2K/8K 固定子集困惑度增幅不超过 1% 的门槛，并重新核算格式变化后的容量。目标是缩小当前速度损失，不承诺一定超过 FlashAttention。

## 优先级 3：混合执行成本与调度控制（系统主线）

- **先降执行成本：**研究混合批次形状分桶、持久化缓冲及 CUDA Graph 可捕获边界；验证动态 query 长度、分页映射、地址稳定性和 padding，记录 Graph 命中、回退与额外存储成本，不假设所有混合批次都可捕获。
- **再改控制器：**执行成本明确后，结合实际可见 ITL、TTFT、等待年龄与 KV 压力调整预算，避免预算持续缩小却增加 Eager 执行次数；与独立调优的固定策略对照，不通过放宽 SLO 美化结果。
- **验收：**覆盖稳定、突发、长短混合及 KV 压力的冻结在线轨迹，报告尾延迟、SLO 有效吞吐、抢占/重计算和等待保护；补做组合消融，明确与 P2/P3/P4 的兼容性及收益边界。

## 收尾：复现与面试准备

- 优先为 P4 补充第二个模型配置或不同 GQA/上下文组合的验证，区分已有形状覆盖与真实模型泛化证据。
- 整理“瓶颈 → 设计 → 正确性 → 性能 → 局限”的图表与复现入口，能解释 FP32 累加、量化粒度、分页生命周期、split-KV 合并及 kernel 提速为何不等于端到端提速。
- 不因简历需要强行推进未通过收益空间关卡的异步流水线，也不将单卡优化或 TP=2 冒烟描述为多卡性能成果。
